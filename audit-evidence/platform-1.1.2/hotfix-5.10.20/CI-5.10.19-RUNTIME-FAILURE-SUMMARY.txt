Root cause confirmed in 5.10.19 qa-p5-runtime.mjs:
The QA HTML transform converted scripts with type application/ghrab-protected into normal text/javascript and removed data-ghrab-protected. The main protected application bundle therefore executed during HTML parsing before the deferred GHRAB Platform 1.1.2 loader was available. The suite-session module correctly failed closed and marked the page blocked. This was a QA bootstrap ordering defect, not a reason to weaken application fail-closed behavior.

Why exactly three init failures:
The runtime audit visits index.html at 1280, 390 and 320 px, then manual/index.html at the same widths. The protected main application has the Platform lifecycle dependency. The three failures correspond to the three main-page widths.

Hotfix decision:
- Do not change production suite-session cleanup logic from 5.10.19.
- Keep protected scripts inert in runtime and Axe harness transforms.
- Wait for the real Platform 1.1.2 runtime.
- Unlock through GHRAB_PLATFORM.unlockProtectedScripts().
- Add a harness sentinel so eager execution cannot silently return.
- Apply the same production-order model to qa:axe because it had the same defect.
